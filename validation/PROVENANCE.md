# Validation provenance

This document explains where the numbers, graphs and regression fixtures in
FreePlots come from. It is part of the public repository so that the evidence
behind the README can be checked from a clean checkout.

FreePlots is independent. It is not affiliated with, endorsed by, sponsored by
or approved by any commercial statistical software vendor. No proprietary
source code, documentation, icons, data files or output from another product is
included in this repository or used as a validation source.

## Validation layers

| Layer | What it proves | Where it lives |
|---|---|---|
| Published formulas and closed forms | The implementation follows the written statistical definition on typical, boundary and invalid input | `crates/*/src`, `crates/*/tests` |
| Independent open-source oracles | A second implementation (Python/NumPy/SciPy/statsmodels/scikit-learn/lifelines) agrees within a stated tolerance | `tools/gen_*.py` → `crates/fp-core/tests/reference/*.json` |
| FreePlots regression fixtures | A later change does not silently alter a report, table or plot that was already reviewed | `validation/freplots/`, `crates/fp-core/tests/golden/` |

The regression fixtures are FreePlots output frozen by this project. They are
not output from another program and they do not establish equivalence with one.

## Datasets

Every CSV under `validation/datasets/` is synthetic and was generated by the
project. There is no customer data, personal data, scraped data or third-party
data set. The files are committed at their exact values, so every check can be
repeated without a generator. They are covered by the project MIT licence.

The datasets are deliberately small and cover the cases named in the test
files: normal, lognormal, Weibull and exponential samples, ties, missing values,
grouped data, control-chart patterns, regression designs and reliability data.

## Independent numeric oracles

The JSON files in `crates/fp-core/tests/reference/` record the tool version that
produced them in their `generated_with` field. The versions currently frozen in
the repository are:

| Oracle | Recorded version | Examples of covered areas |
|---|---|---|
| SciPy | 1.18.1 | distributions, fits, inference, non-parametrics, Box-Cox, tolerance intervals, ALT |
| NumPy | 2.5.4 | PCA, plots, quartiles, Pareto, dotplot, matrix panels |
| statsmodels | 0.15.0 | logistic, ordinal, Poisson, stepwise, time series |
| scikit-learn | 1.9.1 | k-means |
| lifelines | 0.30.3 | Weibull and lognormal reliability |

Some checks are deliberately closed-form rather than library calls: the
Tukey/Fisher tables, Gage linearity, agreement, Laney limits, control-chart
constants and the stem-and-leaf rule are checked against a hand-built
calculation. Those scripts state the formula they implement at the top of the
file.

The Rust tests compare the engine with the stored oracle using explicit
tolerances (absolute or relative); CI never runs Python to produce numbers.

Regenerating an oracle is a deliberate change:

```bash
python3 tools/gen_distributions.py   # requires the version named in the file
cargo test -p fp-core --test reference_values
```

## Tolerances

The comparator used by the oracle tests is part of the Rust test suite. The
conventions are:

- counts and degrees of freedom: exact;
- probabilities and statistics: absolute or relative `5e-4`, unless the
  specific test states a wider bound for a published approximation;
- Anderson–Darling and p-values: absolute `1.5e-3` where the test uses the
  published approximation;
- a missing key is a failure, not silently ignored.

Graph checks compare the rendered SVG structure and the documented axis rules;
they do not claim pixel identity with any other implementation.

## Reproducing the public checks

```bash
cargo test --workspace --locked
python3 scripts/licence-inventory.py --check
```

Everything runs from a clean checkout. No private capture pack, licensed output
or external service is required.

## What this document does not claim

- It is not a legal opinion and not a certification by any standards body.
- It does not claim that every analysis has an independent oracle. The coverage
  table in `validation/RESULTS.md` marks the areas that are still open.
- It does not claim equivalence with any commercial product. Statistical
  formulas, file formats and user-interface conventions are not proprietary to
  one implementation.
