# Validation provenance

This document explains where every number, graph and captured comparison in
FreePlots comes from, and what is deliberately not published. It is part of the
public repository so that the evidence behind the README can be checked without
the private capture pack.

FreePlots is independent. It is not affiliated with, endorsed by, sponsored by
or approved by any commercial statistical software vendor. No proprietary
source code, documentation, icons or data files from another product are
included in this repository.

## Three independent layers

| Layer | What it proves | Where it lives |
|---|---|---|
| Closed-form and property tests | The implementation follows its stated formula on typical, boundary and invalid input | `crates/*/src`, `crates/*/tests` |
| Independent numeric oracles | A second implementation (Python/NumPy/SciPy/statsmodels/scikit-learn/lifelines) agrees within a stated tolerance | `tools/gen_*.py` → `crates/fp-core/tests/reference/*.json` |
| Captured-run comparison | The output agrees with an external commercial package on fixed datasets, for the areas that were captured | private capture pack; public summary in `validation/RESULTS.md` |

The three layers answer different questions. A passing oracle does not prove
that a convention matches another program, and a captured comparison does not
prove that the implementation is correct outside the captured cases.

## Datasets

Every CSV under `validation/datasets/` and `validation/parity19/datasets/` is
synthetic and was generated by the project. There is no customer data,
personal data, scraped data or third-party data set. The files are committed at
their exact values, so a comparison can be repeated without any generator; the
formulas and the sample sizes are described in the validation notes and in
`tools/` where a generator is used. They are covered by the project MIT licence.

The 19-area capture kit also generates its two DOE sheets (`taguchi_l18.csv`
and `plackett_burman.csv`) with the FreePlots design generators before the
comparison, so both sides receive the same runs.

## Independent numeric oracles

The JSON files in `crates/fp-core/tests/reference/` record the tool version that
produced them in their `generated_with` field. The versions currently frozen in
the repository are:

| Oracle | Recorded version | Examples of covered areas |
|---|---|---|
| SciPy | 1.18.1 | distributions, fits, inference, non-parametrics, Box-Cox, tolerance intervals, ALT |
| NumPy | 2.5.4 | PCA, plots, quartiles, Pareto, dotplot, matrix panels |
| statsmodels | 0.15.0 | logistic, ordinal, Poisson, stepwise, time series |
| scikit-learn | 1.9.1 | k-means |
| lifelines | 0.30.3 | Weibull and lognormal reliability |

Some oracles are deliberately closed-form rather than library calls: the
Tukey/Fisher tables, Gage linearity, agreement, Laney limits, control-chart
constants and the stem-and-leaf rule are checked against a hand-built
calculation. Those scripts state the formula they implement at the top of the
file.

The Rust tests compare the engine with the stored oracle with explicit
tolerances (absolute or relative), not by re-running Python. Regenerating an
oracle is a deliberate change:

```bash
python3 tools/gen_distributions.py   # requires the version named in the file
cargo test -p fp-core --test captured_validation
```

CI never runs Python to produce numbers; it only runs the Rust tests against the
committed JSON.

## Captured-run comparison

A subset of areas was compared with an external commercial statistical package
running on a dedicated Windows workstation. The capture procedure is:

1. open the fixed CSV from `validation/datasets/` or
   `validation/parity19/datasets/`;
2. run the analysis with the settings listed in the capture sheet;
3. copy the whole Session text and export the graph;
4. compare the text with `validation/compare.py` and check the graph by hand.

The package is used only as an output oracle. No code, macro, manual text,
icon or data file from it is copied into this repository, and the raw Session
text and graph exports remain in the private capture pack because they are
output of a licensed program. The installed version and edition are recorded in
that private log; the public repository publishes the comparison result and the
dataset, not the licensed output.

`validation/RESULTS.md` is the public result summary. It identifies the dataset,
the analysis, the tolerance and whether the row passed, needed a manual graph
check, or is still open. It does not reproduce the captured text.

## Tolerances

`validation/compare.py` uses:

- `n`: exact;
- Anderson–Darling and p-values: absolute `1.5e-3`;
- every other number: absolute **or** relative `5e-4`.

A missing required label is a failure. A clamped p-value (`*`, `<`, `>`) is
reported and checked by hand. Graph comparisons are visual: axis ticks, axis
range, band edges, fitted line and label placement are checked against the
exported plot at the sizes recorded in the capture sheet.

## Reproducing the public checks

```bash
cargo test --workspace --locked
python3 validation/compare.py --selftest
python3 validation/compare_all.sh        # needs a local capture pack
python3 scripts/licence-inventory.py --check
```

`compare_all.sh` is the only command that needs the private pack. Everything
else runs from a clean checkout.

## What this document does not claim

- It is not a legal opinion and not a certification by any standards body.
- It does not claim that every analysis has a captured comparison. The open
  areas are listed in `validation/RESULTS.md`.
- It does not claim that similar functionality, a similar menu layout or
  matching output implies any connection with another vendor. Statistical
  formulas, file formats and user-interface conventions are not proprietary to
  one implementation.
